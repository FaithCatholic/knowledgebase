This guide is for knowledge base administrators. It covers how KB Chat works, every setting, the background jobs that keep it current, and what to do when something goes wrong. Staff see the chat as FAITH Search Agent; in the admin pages, the agent, assistant and settings are named KB Chat. For how staff use it, see the FAITH Search Agent user guide. The technical reference for developers is the kb_chat module's README in the kb code repository.

How it works

KB Chat is built on Drupal's AI modules. A question goes to the KB Chat AI agent, which runs on Claude (Anthropic). The agent decides which tools to use, calls them, and writes an answer from what they return, with links to its sources.

  • Knowledge base search covers kb pages, Google shared drive files and trusted website pages. They're all held in one search index, kb_chat_content, stored as vectors in a PostgreSQL database (vectordb) on Upsun. Google's Gemini model turns text into vectors.
  • Live tools ask other systems at question time: Trello, the BigQuery data warehouse, the magazine archive (catholicmagazines.org), FAITH publications (the faithmagazine "mothership" site), and the priority documents in Google Drive.
  • Access: every search result is checked against the asking user's permissions before Claude sees it, and the live tools apply the same staff and management split.

Roles and permissions

View staff documents in the kb chat
Google Drive files shared with allemployees@. Granted to FAITH Staff and Management.
View management documents in the kb chat
Drive files shared only with mgtteam@, plus the management data warehouse views. Management only.
Administer KB chat sources
The Google Drive settings, the indexed files list and the trusted websites.
View KB costs
The KB costs this month block.
View KB chat status
The KB chat status block.

kb pages follow the site's normal content access: a page staff can't open never reaches the chat for them. Keep Allow access bypass switched off in the assistant's search settings, or this check is skipped.

The KB Chat agent

Configuration → AI → AI Agents → KB Chat (/admin/config/ai/agents).

  • Agent Instructions tell Claude which tools to use when, which sources to prefer, and how to cite. Type them as plain text. The editor saves typed Markdown with escape characters, and kb removes them automatically on save, so a citation example like [Title](URL) reaches Claude intact.
  • Tools: the agent can only use enabled tools. They are RAG/Vector Search (the knowledge base), Read priority documents, Search the magazine archive, Search FAITH publications, Query the data warehouse and Search Trello. When you enable a tool, describe it in the instructions too.
  • Leave Default information tools empty. A blank entry there breaks the chat.

The KB Chat AI assistant (Configuration → AI → AI Assistants) wraps the agent. Don't set temperature or top-k on it: Claude Opus 5.5 rejects them, and kb strips them as a safeguard.

The assistant's memory keeps one conversation per user for 7 days, sending the last 10 exchanges to Claude as context. The conversation reopens in the chat box until it expires or the user chooses Clear history.

The chat box is the AI DeepChat block. In the Content region it shows inline on the page, with a link to My searches (/my-searches) underneath, where each user sees their own past conversations from the last 30 days. In the block settings, keep both streaming options switched off, or answers hang on the three dots.

Trusted Domains (Configuration → AI → AI Settings, advanced settings) lists the websites answers may link to. The AI module deletes links to any other site from answers, to stop a hidden instruction in a document from sending data to an outside site. It lists kb, Google Docs and Drive, Trello, Catholic Magazines, every digital publishing site and each trusted website. When you add a trusted website or a new publication domain, add its domain here too, or answers can't link to it.

Google Drive

Configuration → Search → KB chat Google Drive (/admin/config/search/kb-chat-drive) has two tabs: Settings and Indexed files.

Which files, and who sees them

Two Google service accounts read the shared drives. One is a member of allemployees@ only, the other of mgtteam@ only. A file the staff account can open becomes a staff document. A file only the management account can open becomes a management document. Google's sharing decides the tier, so to change who sees a file in the chat, change its sharing in Drive.

Only files in shared drives are included. My Drive files, and files shared only with individuals or with "anyone at faithcatholic.com", are not. Supported types are Google Docs, Sheets (every sheet) and Slides, PDF (text only, not scanned images), Word (.docx), Excel (.xlsx), plain text, CSV and Markdown.

Settings tab

Status
When the drives were last listed, how many files are waiting to be read, and any files skipped because they crashed the sync. Re-list the drives on the next run applies your changes within 5 minutes. Try these files again retries crashed files.
Priority documents
Documents the chat checks before others, such as the production schedules and management meeting notes. Enter one per line: the Drive link, then | and what it's for, for example https://docs.google.com/spreadsheets/d/…/edit | Production schedule for all magazines: print, mail and ad deadlines. The note tells Claude when to use the document, so make it descriptive. Under the box, the page shows which document each line found. The chat reads priority documents live from Drive (reused for up to 10 minutes) and still respects their tier. Each one must be in a synced shared drive.
Shared drives to leave out
One drive name or ID per line. Accounts Payable and Magazines are left out.
Folders to leave out
One per line, with everything inside: a path starting with the drive name, like Custom Publishing/Production/2024, or the folder ID from the end of its Drive link. Capitals don't matter, and names with spaces need no quotes.
Skip files whose names contain
Words or phrases, one per line, for files that shouldn't be easy to query, such as contact or donor lists.
Files to leave out
Single files, one per line: the file ID, then its name as a note. The Indexed files tab fills this in for you.
List the drives for changes
How often the drives are checked for new, changed and removed files. The default is every 6 hours.
Largest file / Largest PDF to read
Bigger files are skipped. Large PDFs are usually print proofs, and they can run the sync out of memory.

Indexed files tab

Lists every Drive file in the chat, 50 to a page, with its shared drive, type, who can see it, when it last changed, and how much text it has. Filter by name, drive, type or tier, and sort by any column. Sorting by Text finds huge spreadsheets that can crowd out better results.

  • Ignore selected files takes the ticked files out of the chat immediately and keeps them out.
  • Ignored files, at the bottom, lists everything ignored. Stop ignoring selected files brings files back within one sync.
  • To leave out a whole folder, use Folders to leave out on the Settings tab instead.

How the sync runs

Every 5 minutes a background job checks whether the drives are due for listing. A listing walks every shared drive and queues new and changed files. It also removes files that were deleted, unshared or excluded, but only after a complete listing, so a Google outage never removes anything. Every run then reads up to 100 queued files, for at most 4 minutes. A large first sync, or a big new folder, can take many hours to work through. The status block estimates how long.

Trusted websites

Configuration → Search → KB chat trusted websites (/admin/config/search/kb-chat-websites). These are outside websites the chat searches and cites. Their pages are indexed, not copied into kb, and answers link back to the website.

Name
Who runs the site and what it covers. Answers cite the site by this name.
Start URLs and Only follow links under
Where the crawl starts, and the URL prefixes it may follow. Use the prefixes to keep the crawl to the section you trust.
Include linked PDF, Word and Excel files
Also reads documents on the same site that the pages link to.
Who runs it
FAITH or a third party. Answers say which.
What it is the authority for
One or two sentences given to Claude with every result from the site, saying when to rely on it.
How often the information changes, Who can see it, Most pages to index, Enabled
The re-crawl interval (daily, weekly or monthly), all staff or management, the page cap, and whether it is still crawled.

The list shows each site's indexed pages and last crawl. Crawl now queues a site for the next run, within 10 minutes. The crawler follows robots.txt and reads one page per second.

Some sites block automated readers. USCCB, for example, shows a "Checking connection" challenge on every page except the home page. Those can't be crawled; save the documents you need into a shared drive instead. Sites built entirely with JavaScript may also index few or no pages.

Other sources

Trello
Live search of an approved list of boards, read with a read-only Trello token. Cards from boards not on the list are never shown. The board list is in kb's settings.php. To check which boards the account can see, run drush kb-trello.
Data warehouse
Read-only queries on BigQuery (faith-data-warehouse), limited to views made for the chat: kb_chat for everyone, kb_chat_management for Management. Each query must be a single SELECT that scans at most 1 GB, and returns at most 200 rows. The views leave out customer names and contact details. Their descriptions double as Claude's instructions, so keep them accurate when you change a view.
Magazine archive
Full-text search of every issue on catholicmagazines.org, through that site's search API.
FAITH publications
Search across every publication on the faithmagazine site: Faith Syndicated, Content Evangelist, FAITH Magazine and the diocesan sites. Only published, public articles are returned.

The search index

Configuration → Search and metadata → Search API → KB chat content (/admin/config/search/search-api/index/kb_chat_content) indexes kb pages (Article, Diagram, Basic page and Resource) and Drive and website documents.

  • Keep Index items immediately switched off. A background job indexes changes every 5 minutes. With it on, saving a page waits for Gemini and can time out.
  • Rendered HTML output must stay the only Main content field, using the Default view mode for shared drive documents.
  • To rebuild everything, use Rebuild tracking information or Queue all items for reindexing, then let the background job work through it. Several thousand items take hours, and the chat keeps working meanwhile.

Monitoring

KB chat status block

One screen with everything that feeds the chat. At the top it lists anything that needs a look, worst first, or says everything is running normally. Below that:

  • Content index: items indexed and waiting, by source.
  • Google Drive: documents per tier, last listing, files waiting (with a rough time to finish), and crashed files.
  • Trusted websites: pages per site and last crawl. It warns on sites with no pages or overdue for a crawl.
  • Cron jobs: the last run, duration, result and last success of each background job. "Never finished" means the run was stopped by Upsun's time limit or ran out of memory.

KB costs this month block

  • AI: kb's live estimate and each provider's billed figure for Claude (Anthropic) and Gemini (Google), plus chat requests and the average cost per request.
  • Upsun hosting: this month's open invoice for the FAITH Flex organization, next to last month's. kb is its only project. Resources are billed for the whole month from day one; usage grows until month end.
  • Total this month: AI plus hosting.

If kb's estimate and a provider's billed figure drift far apart, something else may be using the same key, or a price in settings.php is out of date.

Chat logs

Configuration → AI → AI Logging (/admin/config/ai/logging) keeps every chat question and answer for 30 days, including which tools were called. It's the first place to look when an answer is wrong. Indexing isn't logged, because it would fill the database.

Background jobs

These run on Upsun's cron:

kbindex, every 5 minutes
Indexes up to 100 new or changed items.
kbdrive, every 5 minutes
Lists the drives when due, then reads up to 100 queued files.
kbweb, every 10 minutes
Crawls the trusted websites that are due.
drupal, every 19 minutes
Refreshes the Anthropic cost figure and the Upsun billing figures hourly.

Each job has a time limit, so code deploys never wait long for a running job.

Drush commands

Run these on production with upsun drush -e main -- <command>.

kb-drive --drives
The shared drives each account can see, and which are excluded.
kb-drive --folders="Drive Name"
Indexable files per folder, to decide what to exclude.
kb-drive --list
List the drives now.
kb-index
Index a batch now.
kb-web <website machine name>
Crawl one website now.
kb-trello
Check the Trello key, token and board list.
kb-costs
Refresh and print this month's AI costs.

Keys and secrets

These are sensitive Upsun environment variables, never stored in configuration:

  • ANTHROPIC_API_KEY: Claude, for answers.
  • GEMINI_API_KEY: Gemini, for the search index.
  • ANTHROPIC_ADMIN_API_KEY: Anthropic cost reporting.
  • GOOGLE_DRIVE_SA_JSON: the staff Drive and warehouse account.
  • GOOGLE_DRIVE_MGMT_SA_JSON: the management Drive and warehouse account.
  • TRELLO_API_KEY and TRELLO_TOKEN: Trello.
  • MAGAZINE_ARCHIVE_TOKEN: the magazine archive search.
  • MOTHERSHIP_SEARCH_TOKEN: the FAITH publications search.
  • GOOGLE_BILLING_PUSH_TOKEN: Google's billing notifications.
  • UPSUN_API_TOKEN: the Upsun dashboard and hosting costs.

The magazine archive and FAITH publications sites hold the matching tokens: ARCHIVE_SEARCH_TOKEN and KB_SEARCH_TOKEN. When you rotate a token, change it on both sites.

Troubleshooting

The chat shows an error for every question
Check the most recent log message. Common causes are a temperature or top-k value saved on the assistant, a blank Default information tools entry on the agent, or an expired or out-of-credit API key.
The chat hangs on the three dots
One of the DeepChat block's streaming options is on.
A Drive file isn't found
Check, in order:
  • Is it in a shared drive, shared with allemployees@ or mgtteam@?
  • Is its drive or folder excluded, or its name skipped?
  • Is it on Indexed files, or listed under Ignored files?
  • Is it over the size limit, scanned, or protected?
New files can take up to 6 hours, plus queue time.
A staff member sees management information
Check the file's sharing in Drive: if allemployees@ can open it, it's a staff document. For a kb page, check its access settings.
Answers have no links
Check that the source's domain is in Trusted Domains: links to any other site are deleted from answers. Then check that the agent instructions ask for Markdown links using each result's URL.
A website shows few or no pages
The site may block automated readers or build its pages with JavaScript. Check the start URLs and link prefixes, then try Crawl now.
A deploy is waiting
Deploys wait for running cron jobs. The status block shows what's running; every job stops within its time limit.

Making changes safely

Settings changed in the admin pages live in production's database until exported. After changing the agent, assistant, blocks, index or permissions, export the configuration and commit it, so the next deploy or a sandbox copy doesn't lose it. Google Drive settings and trusted websites are configuration too.
